User: "AI sanga chat garna mildaina; 5 chats/day per user limit Redis bata, cooldown UI chat input ma."

## Root causes (chat dead) — 3 stacked
1. **ALL 13 `ai_agents` rows had dead models** (session 1 fixed only `.env AI_MODEL`; DB rows untouched): groq agents = `llama-3.3-70b-versatile` (Groq decommissioned), gemini agent = `gemini-2.0-flash` (Google retired; error msg says use `gemini-3.6-flash`). Verified live Groq model list via `/v1/models`: `qwen/qwen3.6-27b` + gpt-oss-* exist, llama-3.3 gone.
2. **`BaseHandler::ai()` prefix-dedupe bug**: skipped EVERY chain entry whose label starts with primary provider prefix → when agent model was stale, the healthy `groq:qwen/qwen3.6-27b` chain entry never ran. Fixed: exact-label match only.
3. **Prompt TPM blowout**: CustomerSupportHandler embedded 20 nearby places WITH descriptions + 10 alerts + ALL 108 categories (~6KB) → ~6400 tokens vs Groq free-tier 8000 TPM → "sleeping 12s" retries ×3 = 80s responses. Fixed: 5 places no description, 3 alerts (id/title/severity only), 25 categories id/name. Response now ~19s.

## Gotchas learned
- `Invoke-WebRequest` without `Accept: application/json` gets **302→admin login HTML (status 200)** for sanctum failures — always send the Accept header when testing API routes.
- `php artisan route:list` is broken project-wide (pre-existing): web routes reference non-existent `App\Http\Controllers\AdminController` → ReflectionException dumps source. Don't rely on it.
- `reset_at` is ISO8601 UTC ("Z") — Dart parses fine, compare against local now().
- Quota counter can exceed limit by concurrent attempts (used=6 shown) — harmless; remaining floors at 0.
