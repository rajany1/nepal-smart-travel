## FCM HTTP v1 Migration (push actually delivering now)

User reported "aayena notification" after push:test. Root causes found & fixed:
1. `FIREBASE_SERVER_KEY` was empty + legacy FCM API is dead anyway → migrated to **HTTP v1** via `kreait/firebase-php:7.15`.
2. XAMPP PHP lacked ext-sodium (kreait dep) → uncommented `extension=sodium` in C:\xampp\php\php.ini.
3. kreait/laravel-firebase incompatible (needs L11/12 or PHP ≤8.2) → used standalone SDK directly.
4. `CloudMessage::toToken()` doesn't exist in 7.x → use `->withChangedTarget('token', $t)`.
5. **User settings had `push_notifications: false`** (master kill-switch) — silently excluded the token! Flipped user 1 to true in DB. App Settings toggle controls this.
6. User placed service account JSON at `backend/storage/app/firebase-credentials.json`, project `smart-travel-app-499714-cbd3f`; `.env` FIREBASE_CREDENTIALS set.

Result: `FCM push result: sent=1, pruned=0, lang=en` at 22:47:30. sendFcm now: per-token v1 send, UNREGISTERED tokens auto-pruned (`subscribed=false`), bilingual data payload unchanged. Mobile location sync timer verified working in access logs (5-min PUT /push-tokens/location).
