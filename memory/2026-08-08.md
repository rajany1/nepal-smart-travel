# 2026-08-08 — OSM Place Duplicates Fix + Flutter Save Button

## Problem
- `PlaceController::store()` had no duplicate checks → users could resubmit an OSM place already in DB (or same name+coords) → duplicate rows (user report: "places haru duplicate aako xan").
- `osmStatus()` filtered by `created_by = user` → admin-imported OSM places (source=osm) showed save button even though already in DB; guest save → 401 unhandled (ugly error snackbar).
- `AdminController::createPlace()` (quick import form) didn't send/accept `osm_id` → admin importing the same OSM node twice created duplicates (osm_id column was null on admin-created rows? No — quick import sent no osm_id at all).
- ~22 existing duplicate rows in DB (same name + rounded coords, e.g. "Elite Cafe" #677/#3708, "R" x3 junk, "temple" x2).

## Fixes (all implemented + verified)
1. **`PlaceController::store()`** — reject 409 if `osm_id` already in DB (any user) OR same normalized name within ~150m (haversine). Verified via script: resubmitting "The Lakeside Retreat - Pokhara" at its coords → SIMILAR MATCH.
2. **`osmStatus()`** — removed `created_by` filter; global lookup by osm_id → admin-imported OSM places now return `approved` → app hides save button. (NOTE: user-scoped pending/rejected states still work since global row found first.)
3. **`nearbyCombined()`** — cross-source dedup: OSM results filtered out if osm_id exists in DB, or same name within ~100m (covers legacy admin rows w/o osm_id).
4. **`AdminController::createPlace()`** — accepts `osm_id` + `source`; blocks duplicate osm_id and similar name+coords with clear flash error + audit log `place.duplicate-blocked`.
5. **`places_osm.blade.php`** — hidden `osm_id`/`source` fields in quick import form; JS prefill sets them; OSM list shows "In DB" badge (from new `in_db` flag in `placesOsm()`) instead of download button for already-saved nodes.
6. **`ImportOsmPlaces.php`** — legacy merge: if osm_id not found but a null-osm_id row matches name+~200m coords → attach osm_id (no new row).
7. **NEW `places:dedupe` command** (`--dry-run` supported) — groups by LOWER(TRIM(name))+ROUND(lat,3)+ROUND(lng,3); keeps best (verified>active>rating>desc>id); moves place_images, place_reviews, model_translations (note: column is `translatable_type`/`translatable_id`, NOT model_type — first run crashed on that!) to kept id; deletes dups in transaction. **Ran: merged 22 places / 21 groups; now 0 dup groups, 3638 total places.**

## Flutter
- **`add_place_screen.dart`**: wired `connectivity_plus` (6.x — `checkConnectivity()` returns **List**, use `result.isNotEmpty`); `_submitPlace` error handling: 401 → login redirect; 409 → orange snackbar with server message + pop(false); 422 → first validation error; connection timeouts → auto queue offline + pop(true); fallback generic.
- **`nearby_map_screen.dart`**: `_confirmSaveOsmPlace` checks `AuthProvider.isAuthenticated` → guest gets "Login required" dialog → pushes `LoginScreen`; after AddPlaceScreen returns, refresh `_checkOsmSubmissionStatuses()` on non-true result (so already-in-DB places hide the button).

## Gotchas
- Laravel `model_translations` uses `translatable_type`/`translatable_id` (model translation package), not `model_type`.
- `places:dedupe` reviews move can fail on unique(user_id, place_id) → warn + cascade delete acceptable.
- PowerShell breaks on raw SQL parens in tinker --execute → use temp PHP script bootstrapping Laravel.
- connectivity_plus ^6.1.1 returns List<ConnectivityResult> — old `!= ConnectivityResult.none` is a type error.
